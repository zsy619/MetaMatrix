# 生产配置与快捷键

上线前核对下面几项。计数和限流都在进程内存里，不新建业务表。

## JWT_SECRET

`JWT_SECRET` 必须换成足够长的随机值，不要使用仓库里的开发默认值。令牌为 HS256，有效期 7 天。剩余不足 24 小时且令牌仍有效时，客户端会调用 `POST /auth/refresh` 续期。已过期的令牌会被拒绝，需要重新登录。

## CORS

`CORS_ORIGINS` 是逗号分隔的允许来源。不要写成 `*`：通配符会被忽略，并退回本地开发源 `http://localhost:5173` 与 `http://127.0.0.1:5173`。只填写实际的前端地址。

## 登录限流

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `LOGIN_WINDOW` | `15m` | 滑动窗口，至少 1 分钟 |
| `LOGIN_PAIR_LIMIT` | `8` | 同一 IP + 邮箱的失败次数上限 |
| `LOGIN_IP_LIMIT` | `30` | 同一 IP 的失败次数上限 |

超过上限返回 `429`，`code` 为 `rate_limited`，并带 `Retry-After`。成功登录只清掉该邮箱的计数。

## 图形验证码

登录和注册都要先取 `GET /auth/captcha`，提交时带上 `captchaId` 与 `captchaCode`。
验证码由服务端生成和校验，一次性使用，前端只负责显示图片。

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `CAPTCHA_TTL` | `5m` | 验证码有效期，范围 30 秒到 1 小时 |
| `CAPTCHA_DEBUG` | `false` | 调试模式，会在 `/auth/captcha` 响应里附带 `debugAnswer` |
| `CAPTCHA_DEBUG_LOOPBACK` | CI 里为 `true`，其余为 `false` | 只有回环地址（127.0.0.1 / ::1）能拿到 `debugAnswer` |

**`CAPTCHA_DEBUG` 只能在本机和 CI 打开。** 生产环境一旦置为 `true`，
任何人都能直接读到验证码答案，图形验证码就形同虚设。

`CAPTCHA_DEBUG_LOOPBACK` 是给自动化用的窄口径开关：只有请求来自本机回环地址
才带答案，外部调用者拿不到。CI 里检测到 `CI=true` 或 `GITHUB_ACTIONS=true`
会自动打开它，冒烟脚本和 API 跑在同一台机器上，可以完成一次真实的
「取图 → 填答案 → 提交」闭环；生产环境不会自动打开，需要时请显式设置。

验证码图片由服务端渲染成 PNG（自带 5x7 点阵字库），图里没有能直接读出的明文答案。
同一个来源 1 分钟内最多取 60 张，超了返回 429 `rate_limited`。

答案是 **6 位**，字符集为 **大写字母 + 数字**（`A-Z` 去掉 `I`、`O`，加上 `2-9`），
共 32 个字符，组合数 32^6 ≈ 10.7 亿。比对时不区分大小写，用户用小写键盘敲字母也能通过。
`I`、`O`、`0`、`1` 因为形近被剔除，服务端不会生成，前端输入框也会过滤掉，
避免用户看错后白白浪费一次重试机会。

前端把答案输入框做成"一个输入框 + 六个等分格子"，格子和服务端位数一一对应。
改 `captchaLength` 或 `captchaAlphabet` 时，**必须同步** `pros/web/src/utils/captcha.ts`
里的 `CAPTCHA_LENGTH` 和 `ALLOWED_CHARS`，否则会出现"图片上的字符输不进去"。

### 多实例部署注意

验证码当前存在**进程内存**里，带 TTL 自动过期。API 跑多个副本时，
用户在 A 副本取到的验证码，到 B 副本提交会判定为无效。多实例部署前必须把
`service.CaptchaService` 的存储换成共享介质（Redis，或一张带 TTL 的表），
否则登录会随机失败。进程重启后未使用的验证码会失效，属于预期行为。

## 邮件与找回密码

找回密码的验证码通过 SMTP 发出，代码里是**厂商无关的通用 SMTP**，不需要改代码，
只改环境变量就能换服务商。

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `MAIL_MODE` | `auto` | `smtp` 强制走 SMTP（配置不全则启动失败）；`log` 只把邮件写进日志；`auto` 见下 |
| `SMTP_HOST` | 空 | 服务商提供的发送服务器 |
| `SMTP_PORT` | `587` | `587` 走 STARTTLS；`465` 走隐式 TLS（代码自动识别） |
| `SMTP_USERNAME` | 空 | 登录账号，通常是发信邮箱全称 |
| `SMTP_PASSWORD` | 空 | 登录密码或服务商生成的 SMTP 专用密码 |
| `SMTP_FROM` | 空 | 发件人地址，多数服务商要求与登录账号同域 |
| `SMTP_FROM_NAME` | `元矩阵 MetaMatrix` | 发件人显示名，中文会自动做 RFC 2047 编码 |
| `SMTP_INSECURE` | `false` | 跳过证书校验，只能用于自签证书的内网中继 |
| `SMTP_TIMEOUT` | `15s` | 整段 SMTP 交换的超时 |

`MAIL_MODE=auto` 的规则：配置完整就用 SMTP；不完整时，开发环境（`APP_ENV` 不是
`production`）退回日志通道，生产环境退回"禁用通道"——接口返回 503 `mail_unavailable`，
**不会假装发送成功**。这样生产环境忘了配 SMTP 会立刻暴露，而不是让用户对着一个永远
收不到的验证码反复重试。

日志通道会把整封邮件打进 API 日志，开发时直接搜验证码即可；
配 `RESET_REVEAL_CODE=true` 还能让它顺带出现在 `/auth/password-reset/request`
响应里（只在日志通道下生效，生产永远不会回显）。

### 免费发信方案

| 服务商 | 免费额度 | 主机 / 端口 | 备注 |
| --- | --- | --- | --- |
| Brevo | 300 封/天 | `smtp-relay.brevo.com` / 587 | 注册即用，发件域名最好先做 SPF、DKIM |
| 阿里云邮件推送 | 2000 封/天，日发 200 | `smtpdm.aliyun.com` / 465 | 需先建发信地址并完成域名验证 |
| 腾讯云 SES | 按量计费，有免费额度 | `smtp.qcloudmail.com` / 465 | 需在控制台申请发信模板 |
| QQ 邮箱 | 个人邮箱日限约 50 封 | `smtp.qq.com` / 465 | 用「授权码」当密码，不要填登录密码 |

465 端口是隐式 TLS，587 是 STARTTLS，两者代码都支持，填端口即可切换。
用 QQ 邮箱、Gmail 这类个人邮箱时，`SMTP_USERNAME` 和 `SMTP_FROM` 通常都要填同一个地址。

### 找回密码的频率限制

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `RESET_CODE_TTL` | `10m` | 验证码有效期 |
| `RESET_CODE_MAX_ATTEMPTS` | `5` | 同一验证码最多试错次数，用尽即作废 |
| `RESET_COOLDOWN` | `60s` | 同一邮箱两次发码之间的最小间隔 |
| `RESET_HOURLY_PER_ADDRESS` | `5` | 同一邮箱每小时最多发几次 |
| `RESET_DAILY_PER_ADDRESS` | `10` | 同一邮箱每天最多发几次 |
| `RESET_HOURLY_PER_IP` | `20` | 同一 IP 每小时最多发几次 |
| `RESET_REVEAL_CODE` | `false` | 日志通道下把验证码回显到接口响应（仅开发） |
| `RESET_UNKNOWN_EMAIL_MODE` | `explicit` | `explicit` 未知邮箱返回 404 `email_not_registered`，直接提示"这个邮箱还没注册"；`uniform` 未知邮箱也返回同样响应 |

四个维度是同时生效的：只限邮箱挡不住同一 IP 批量试探，只限 IP 挡不住分布式撞库。
限流检查在查询用户**之前**执行，否则"这次被限流了"本身就会变成账号存在性的信号。

默认是 `explicit`：邮箱没注册时，页面会直接提示"这个邮箱还没有注册"，用户不会对着
一个永远收不到的验证码反复重试。代价是这个接口可以被用来试探某个邮箱是否注册过。
如果不希望暴露账号是否存在，把它设成 `uniform`：未知邮箱也返回与已注册完全一致的
响应，此时页面只会说"如果该邮箱已注册，验证码会很快送达"。
变量写错时会回落到 `uniform`，避免拼写错误意外放开账号枚举。

验证码只存 SHA-256 摘要，不存明文；改密令牌同样只存摘要。数据都在
`core_password_reset_tokens` 表里，没有进程内状态，多实例部署不需要额外改造。

## 分享链接

当前文档接口都要求登录，并且只允许访问本人的画布。公开只读链接会新增一条未登录访问路径，本阶段不做。

## 工作面板统计

`GET /documents/stats` 只统计当前登录用户。查询参数 `scope` 不会放宽范围。响应异常或字段缺失时，页面会把数字补成 0，而不是整页失败。导出 CSV 在浏览器里生成，内容就是当前屏上的趋势，不另建表。

## 一键启动

在仓库根目录：

```bash
docker compose up --build
```

这会启动 Postgres 16（宿主机 `5433`）、API（`3000`）和网页（`8080`）。网页把 `/api` 转到 API。`GET http://localhost:3000/health` 与容器健康检查相同：数据库可连时 `200` / `ok`，否则 `503` / `degraded`。

只在本机跑 Go、单独起数据库时，仍用 `pros/api/docker-compose.yml`。不要同时占用同一个 `5433` 端口。

`JWT_SECRET` 在 Compose 里默认为开发值。上线前用环境变量换成随机长字符串。`CORS_ORIGINS` 默认是 `http://localhost:8080`，要和网页实际来源一致。

## 备份

账户页可以下载本人未归档画布的 JSON 包（最多 200 份），再导入为新画布，不会覆盖原件。单次导入最多 50 份。整库用：

```bash
docker compose exec postgres pg_dump -U metamatrix metamatrix > metamatrix.sql
docker compose exec -T postgres psql -U metamatrix metamatrix < metamatrix.sql
```

## 缓存

`GET /documents`、`GET /documents/:id` 和备份接口是 `Cache-Control: private, no-store`。统计接口是 `private, max-age=20`。浏览器里的统计缓存按用户 id 分开，退出登录会清掉。

## 依赖

直接依赖的 KaTeX 是 `0.19.1`。Mermaid `11.17.2` 自带一份 `katex@0.16.47`，只给图里的公式用。现有版本范围内没有单独的安全升级可做，这一批不改编辑器依赖，避免整包重编译带来不确定的画布变化。

## 健康检查与指标

`GET /health` 探测数据库。正常为 `200` / `ok`，数据库不可用为 `503` / `degraded`，并带上运行时长和请求分档。Compose 里的 API 健康检查打的就是这个地址。

`GET /metrics` 是 Prometheus 文本。访问日志里的 `request_id` 与错误 JSON 的 `requestId` 相同。如果调用方传入合法的 `traceparent`，访问日志会一并记下。

## 快捷键

| 按键 | 作用 |
| --- | --- |
| Ctrl 或 ⌘ + S | 保存当前画布 |
| Esc | 关闭最大化面板、资料预览或版本对话框。同一时间只有一个面板可以最大化 |
| Alt + 1 | 回到模板库 |
| Alt + 2 | 打开工作面板 |
| ? | 打开或关闭快捷键说明 |

在输入框、文本区或正文编辑器里，除保存以外的快捷键不会触发。
